# AASystem: pointee 범위 taint / Store 증거 계약

실험적 정적 분석 기능이다. 대상 바이너리를 실행하지 않으며 Windows 드라이버
지원·자동 취약점 판정·실행 경로·최종 callback 등록 상태를 보증하지 않는다.

## 1. 메모리 내용 소스

기존 `flow_create_implicit_analysis.seeds`에 `kind: "pointee_range"`를 추가했다.
필수 필드는 `schema_version: 1`, `pointer_node_id`, `interval: {start,end}`,
`labels`, `binding_mode`, `point: "after_pointer_definition"`이다.
예를 들어 `interval: {start:0,end:8}`은 선택한 포인터 정의 **직후**의 8바이트다.

- entry `InputValue` 또는 루프 밖의 포인터 폭 `Load`를 선택한다. 구조체에서
  포인터를 읽은 `Load`도 지정할 수 있다. 포인터 주소 라벨과 내용 라벨은 별개다.
- `require_program_derived_exact`: 기존 분석에서 단일 non-null 객체가 확인되어야 한다.
- `analyst_assumed_exact`: 확인되지 않은 경우 분석자가 유효한 non-null 메모리를
  가리킨다고 명시적으로 가정한다. 가정은 증거에 남으며 별칭 없음으로 승격하지 않는다.
- 두 모드 모두 “이 내용은 사용자 입력”이라는 판단은 분석자 책임이다. `SystemBuffer`
  이름, WDM 오프셋, 함수별 외부 규칙으로 자동 분류하지 않는다.
- 이전 읽기에 소급하지 않고, 모든 버전이나 모든 접근에 반복해서 라벨을 붙이지 않는다.

완료 결과의 **새** `ssa_artifact` / `graph_artifact`를 사용한다.
`pointee_certificate_artifact`는 `flow_get_pointee_evidence`로 페이지 끝까지 읽는다.
원본과 결합된 그래프, 포인터 가정, 실제 source 라벨 digest를 다시 검증한다.
`flow_get_implicit_analysis`의 fact가 seeded 라벨을 제공한다.

fact의 `explicit_bit_ranges`는 값 내부의 비트 위치다. little-endian에서
`[0,8)`을 source로 지정한 뒤 `[0,4)`를 정확히 덮고 64비트를 읽으면 남는 범위는
`{label: "REQUEST", bit_offset:32, width_bits:32}`이다. 범위 필드가 없다는 이유만으로
clean이라고 하지 않는다. 전체 라벨, unknown, alias precision을 함께 확인한다.

## 2. 범용 Store 증거

`flow_check_store`에 다음을 제출한다:

```text
ssa_artifact, store_node_id, base_node_id,
byte_offset, target_function, request_key,
member_path (선택: ["callbacks", 14] 같은 필드/배열 경로)
```

작업 완료 뒤 `store_evidence_artifact`를 같은 도구의 `artifact_id`로 페이지 조회한다.
증거는 Store 목적지의 base+offset, 저장값의 전체 포인터 폭과 함수 entry 주소,
SSA 변환 경로, 실제 IDB의 함수/선택적 타입 레이아웃 관측을 결합한다.
타입 정확성은 명시적 가정이다. 함수 이름이나 xref만으로 성공시키지 않는다.

`proven_in_scope`는 **“해당 Store가 실행된다면, 기록된 가정 아래 그 슬롯에 그 함수
주소를 쓴다”**는 뜻이다. 이후 덮어쓰기 없음·모든 경로 등록·실제 callback 호출을
증명하지 않는다. `unknown`과 `mismatch`는 안전/취약점 판정이 아니다.

v1 기존 요청은 유지된다. 큰 주소는 `flow-wire/2` snapshot과 tagged integer를
사용한다. source 라벨만 다른 동일 그래프의 certificate를 다른 분석에 섞어도 거절한다.
tool call의 `database`는 계속 `idb_open`이 반환한 세션 ID이며 경로가 아니다.

## 검증 범위

`tests/flow_core/native_pointee_store_probe.py`는 자체 작성한 C fixture를
IDA 9.3 / Hex-Rays 9.3.0.260213에서 정적으로 검사한다. x86_64·arm64
Mach-O O1의 총 8개 관측이 통과했으며, 실제 출력은
`tests/flow_fixtures/manifests/pointee_store_native.json`에 보존했다.
부분 clear 뒤 Load와 Return의 지정 라벨은 상위 32비트에만 남는다.
정상 Store는 조건부 증명, 잘린 주소는 unknown, 다른 주소는 mismatch다.
`unknown_provenance: true`는 그대로 보존됐다. 모든 소유 세션은 `save=False`로
닫았고 입력 hash는 불변이다. 이 검증은 Windows 커널·TLS·MMIO 모델 검증이 아니다.
